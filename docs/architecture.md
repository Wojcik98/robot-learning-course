# Course data flow

The course uses one locked LeRobot environment and small adapters around its policies. LIBERO supplies two 256 × 256 RGB cameras and an eight-value robot state. The policy processor maps these inputs to the saved checkpoint format. The postprocessor maps a predicted action back to the seven-value LIBERO relative controller input.

`ObservationPacket` records the episode, reset, sequence, observation tick, capture time, camera order, state schema, and task identity. `PolicyRequest` records the checkpoint identity and trained horizon. `ActionChunk` records the request and observation that produced its actions, its first available tick, controller period, bounds, and padding mask. The packet schema rejects missing or reordered cameras, nonfinite state or actions, invalid shapes, out-of-range actions, and changed horizon settings.

The [action queue](../src/vla_lab/runtime/action_queue.py) indexes a chunk from its observation tick. A late chunk skips actions for ticks that have passed. For one tick, it can use the newest valid action or average aligned predictions from more than one chunk. A reset or task change clears the queue. The [virtual scheduler](../src/vla_lab/runtime/virtual_scheduler.py) delivers replies on 50 ms controller ticks. It rejects duplicate, reordered, exhausted, and old-reset replies. It records underflow, observation age, queue depth, and camera or policy availability. The [episode runner](../src/vla_lab/runtime/experiment.py) uses that scheduler with one simulator reset. It does not start a network server.

The [state evaluator](../src/vla_lab/evaluation/states.py) checks explicit state IDs against the frozen split. Development IDs are 0–19 for the selected tasks. Final IDs 20–49 require an explicit final-evaluation flag. It keeps each attempt in a JSONL file, including policy and infrastructure errors. Live ACT evaluation saves one video and run record per state. A policy fault keeps a partial video when at least one frame was captured. The [paired report](../src/vla_lab/evaluation/paired.py) requires the same ordered state IDs for both policies. It gives Wilson intervals, a paired success difference, and an exact McNemar result. It does not compute a policy comparison result when an infrastructure error occurred.

The simulator controller runs at 20 Hz in relative mode. Dataset action labels are at 10 Hz. The current pipeline does not resample those labels. The action schema names the controller's native rotation and gripper inputs; it does not claim that these normalized values are physical distances or angles. Camera order is checked from the packet labels. The software cannot infer a camera swap if an upstream source labels the wrong image with the expected name.

The ACT training suite selects a prefix of complete training episodes for each data variant. It keeps the original validation IDs and writes a run-specific split and state/action statistics. The saved processor and checkpoint carry the selected split hash. The full-data variant reuses the frozen full-training statistics. A fixed permutation per epoch maps each training step to a batch. A new run can resume from a complete checkpoint with its model, optimizer, and PyTorch random state. The older P0 checkpoint has no random state and cannot support that exact continuation. The [Lab 3 reference](../artifacts/reference/act/lab3_suite.json) records one-seed development results; it does not use final states.

The [keyboard recorder](../src/vla_lab/data/keyboard.py) passes the same seven-value controller action to LIBERO and saves the applied action with its pre-action observation. A complete file has one more observation than action. The [recovery adapter](../src/vla_lab/data/recovery_dataset.py) uses every 50 ms controller tick. It does not infer human intent or task success from the saved file. Lab 8 has a live injected-key replay. The user retested the revised keyboard window and reported that its controls work.

The [SmolVLA chunk adapter](../src/vla_lab/runtime/smolvla_chunks.py) uses one checkpoint, processor, and request-specific noise seed across runtime modes. The checked [RTC guidance](../src/vla_lab/rtc/guidance.py) uses the model derivative and a clipped guidance weight. The [runtime comparison](../src/vla_lab/experiments/runtime_modes.py) uses fixed virtual availability and saves one result per state and mode. Wall-clock request time is measured separately. The fixed 100 ms virtual delay is shorter than the measured request time on this host. The [final report](../artifacts/reference/runtime/final_modes.json) is a static LIBERO study; it does not show real-time execution or performance on a physical robot.

The [operations guide](operations.md) traces checkpoint hashes, saves release records, and changes a release pointer for rollback. The course has no release service and no robot deployment backend. Lab 11 changes only files in a temporary directory.
